# Automated desktop lifecycle acceptance

This QA flow uses the existing Rust, WebdriverIO 9 and Tauri driver 2.1.0 infrastructure. Production source, IPC permissions, origin classification, application ID and standard profile paths remain unchanged. The desktop test app has identifier `click.qbit.toolbox.e2e` and uses one fresh direct child of OS temp named `qbit-hotkeys-e2e-*` per run. Restart cycles deliberately reuse that run's root.

Existing shutdown failure tests are reused rather than duplicated. The OS boundary in the service test is a fake backend; typed dispatch uses the real compiler, published map and hot path. It does not install hooks or send keys. Feature OFF proves ingress ownership is stopped; a detached synthetic call to an old map would not model a stopped hook. Real OS hook stop acknowledgements use the existing FFI fakes and remain separate from hardware testing.

## Invocation and isolation

Routine CI-safe verification is `bun run check`; it includes the harness isolation unit tests and workspace Rust tests, with the existing interactive hook test ignored. The opt-in Tier B output target remains excluded.

The normal `quality` job remains on `windows-latest`. A separate `desktop` job requires quality success, checks out the same workflow source, and builds `target/e2e/release/qbit-desktop.exe` on `windows-2022` before explicitly selecting its disposable test desktop:

```powershell
bun run e2e:build
$env:QBIT_E2E_ISOLATED_DESKTOP = '1'
bun run e2e:desktop
```

The runner additionally requires GitHub Actions with `RUNNER_ENVIRONMENT=github-hosted`, Windows, no existing Qbit process, the exact isolated executable and driver, and a new canonical temp root. These environment selectors express the CI operator's authorization; they are not a security attestation. Do not set them on a normal workstation. Other VMs remain blocked pending an explicit provisioning contract. No GUI E2E may run solely because no normal Qbit process is present. No autostart UI action or registry mutation is exercised.

Focused WebDriver capture uses only fixed benign Disable fixtures. The first journey rejects a duplicate Ctrl+Shift+F12 with the specific `An enabled mapping already uses this trigger.` conflict and disabled Save, then edits that mapping to Ctrl+Shift+F11 with the whole feature OFF. It verifies the same mapping ID, exact trigger/action payload, new UI trigger and absence of stale F12 text, then publishes in the same host. The extended Rust service acceptance test proves the actual old-trigger/new-trigger dispatch after a trigger/action edit without a backend restart. WebDriver events do not prove physical HID delivery. There is no Win32 SendInput in these desktop tests.

Every scenario emits `results.json` and standard `junit.xml`, with fixed fixture state, PID/start transitions, integrity and exit/handle-release evidence in `events.jsonl`. Runner preflight emits `preflight.json` on BLOCKED. `owned-processes.json` and `cleanup.json` record descendant cleanup; a watchdog bounds the run. Only recorded descendants are eligible for cleanup, with executable and creation time rechecked to prevent PID reuse. Unknown identity refuses cleanup. No executable-name or port-based global kill is used. Temp fixtures and reports are retained; WAL/SHM presence is not treated as a resource leak. CI uploads `.ai-bridge/desktop-lifecycle/` even on failure.

SQLite queries use Bun's existing read-only SQLite API, fixed query text, canonical fixture paths and `PRAGMA quick_check`. Exclusive probes open only those two temp DBs read-only with Windows sharing disabled after graceful host exit. They do not delete or rewrite DB files.

The inspector distinguishes `persistedDesired: null`, `configured: false`, `effectiveDesired: 0` on a fresh profile from a saved OFF row (`persistedDesired: 0`, `configured: true`). Every post-toggle and Quit/restart assertion requires the actual stored row and existing feature database; an absent row cannot satisfy OFF durability. Unsupported values, duplicate intent rows, mapping ID/enabled disagreements with payload, and integrity errors reject. Ordinary harness tests use isolated temp SQLite to cover missing/OFF/ON, invalid/ambiguous intent, mismatched payloads, and unchanged DB hashes.

The process observer samples descendant relationships and creation times; a parent that exits before observation may leave an unowned helper. Preflight refuses existing app/driver processes, and the final scan refuses PASS if any app/driver remains after recorded-owner cleanup. Unknown leftovers produce `BLOCKED_CLEANUP_UNKNOWN_OWNERSHIP` and are never adopted or killed by name. This failure path needs execution in the authorized CI environment alongside the GUI scenarios.

## CI environment reliability and report failures

The image-family choice is a temporary, evidence-based workaround for [runner-images #14738](https://github.com/actions/runner-images/issues/14738): the reporter observed the same application succeeding on Windows 2022 and failing with `DevToolsActivePort` on the newer image. The maintainer closed it as not planned on September 22, 2026, identifying evergreen WebView2 as outside image control. [WebView2Feedback #5415](https://github.com/MicrosoftEdge/WebView2Feedback/issues/5415) describes a related multi-driver crash; it does not prove this application's failure. Windows 2022 is not a permanent compatibility guarantee.

The first real [PR #13 run](https://github.com/qbit-hub/qbit-toolbox/actions/runs/41230330765) stopped in setup: the installed WebView2 was `131.0.2903.86`, while the image-global EdgeDriver was `156.0.4314.42`; zero GUI scenarios executed. The old version-output parser also rejected the driver's output. The correction explicitly provisions the official Microsoft `131.0.2903.86` x64 driver in `.ai-bridge/e2e-tools/edgedriver/131.0.2903.86/`. It never overwrites global tools or changes WebView2 installations.

`tools/desktop-e2e-driver.json` pins the exact HTTPS Microsoft distribution URL, version, archive SHA256 `16ad3ea073e26f0000d1315e0a851eeb44b2754c66d47652e265cce5dea662af` and extracted executable SHA256 `c34a6b22814a18599f2a67bef922ba879ae44158f216d4d2df797d293f545665`. These pins were obtained from the official distribution and independently checked against the executable's valid Microsoft publisher signature and `131.0.2903.86` file version. They are review-controlled source pins, not dynamically trusted download metadata. The provisioning step requires authorized hosted CI, refuses an existing private version directory or reparse-point ancestry, disallows HTTP/redirects, bounds download size/time, verifies the archive before extracting only its unique root `msedgedriver.exe`, and verifies binary hash/version/signature before selecting its absolute path. No arbitrary archive paths are expanded. Failure retains `provisioning.json` and complete BLOCKED scenario reports.

`tools/desktop-e2e-environment.ps1` reads the OS/build, ImageOS/ImageVersion, source HEAD, registered WebView2 version and executable versions/hashes/signatures. It requires the explicitly provisioned private driver; no PATH/global-driver fallback exists. It checks the runtime's first three version components against the pinned driver as required by [Microsoft's driver guidance](https://learn.microsoft.com/en-us/microsoft-edge/webdriver/). Runtime drift to another build fails closed and requires a separately reviewed pin update. The environment report is repeated before GUI launch and retains `environment.json` even on failure. The bounded `--version` probe accepts the Microsoft `MSEdgeDriver` and `Microsoft Edge WebDriver` prefixes, sanitizes control/terminal escapes, rejects ambiguous output/nonzero exits and verifies the reported version against the signed, pinned file version. Probe stdout/stderr are retained up to 4096 characters; its timeout kills only that owned probe child. The Tauri service's `autoDownloadEdgeDriver: false` remains enforced. The only acquisition is the explicit provisioning step, and no runtime is downloaded or replaced.

The shared PowerShell validators have 29 deterministic regressions for output formats/bounds, first-three-component compatibility, missing tools, archive/binary tampering, signature/publisher failures, pinned path/version enforcement and authorization/path refusal. Ordinary isolation tests invoke these pure fixtures; they do not execute a driver, download software, read the registry or set CI selectors. Real provisioning and GUI compatibility still require the hosted run.

Reports distinguish `ASSERTION_FAILURE`, `MISSING_CASE`, `PROCESS_LAUNCH_FAILURE`, `PROCESS_INTERRUPTED`, `WEBDRIVER_BOOTSTRAP_FAILURE`, unauthorized environment and cleanup identity failures. Setup/session-creation failures are BLOCKED, never GUI regression PASS. All three scenario records are completed even after synchronous spawn errors, asynchronous no-PID spawn errors, interruptions, or cleanup exceptions. Safe fake-child tests cover those orchestration paths without creating a process, driver, window or hook. Worker log tails and runner outcomes are retained. An already passed case remains an executed case, while a later run/cleanup failure is separately recorded and forces a failing run. Malformed reports fail closed.

The workflow triggers only for pull requests and pushes to `main`. A scoped correction is delivered through existing PR #13; source changes must be committed and pushed before CI can see them. Merely setting [the documented runner selectors](https://docs.github.com/en/actions/reference/workflows-and-actions/variables) or adding YAML does not constitute execution evidence. Require actual three-case PASS artifacts and clean teardown before accepting the GUI coverage; `reloadSession` after host exit remains unproven until that run succeeds.

## Remaining acceptance

The review correction's workstation validation on October 31, 2026 passed four targeted SQLite regressions, all 15 safe harness tests, 86 Hotkeys Rust tests and the full check (134 workspace Rust and 20 frontend tests, with one interactive hook probe ignored). Formatting, workspace Clippy, Node syntax, PowerShell source parsing and YAML structural checks passed. `actionlint` was unavailable; these checks do not execute the hosted workflow. JavaScript audit exited zero with four findings below the high threshold; Rust audit exited zero with 11 allowed warnings. Exact commands, logs, preservation hashes and candidate lineage are recorded in `.ai-bridge/lifecycle-review-verification.json` and `.ai-bridge/agent-status.md`.

The actual desktop command exited 1 at the environment authorization preflight and emitted three BLOCKED records, zero executed GUI scenarios. The Windows diagnostic script, native GUI build, runtime/driver bootstrap and `reloadSession` have not been executed on this candidate. Safe fake-child failures establish reporting behavior only. Current lifecycle status remains `BLOCKED_E2E_ENVIRONMENT`.

GUI scenarios must pass on the authorized Windows CI desktop before this coverage is accepted. On an uncontrolled workstation report `BLOCKED_E2E_ENVIRONMENT`, with compilation/static and CI-safe test results separately identified. The OFF-intent restart variation is mandatory; ON-intent restart is covered by the fake native service test and is not a GUI requirement.

Tier B OS-output remains feature-gated, ignored and unexecuted unless separately authorized on an attested disposable VM. Tier C remains NOT RUN without a physical HID rig. Earlier manual observation of an emission-counter increment proves only that limited observation; it does not prove the target shortcut reached an application. Release-only physical/HID validation and human Stage approval remain separate gates, without repeating routine UI/persistence work manually.
